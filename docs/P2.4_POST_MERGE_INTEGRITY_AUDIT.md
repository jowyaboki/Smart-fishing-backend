## 1. Executive Summary & Objective

Following the merge of Milestone P2.4 (`feat/p2-4-empirical-tide-validation-engine`), a focused post-merge integrity audit revealed redundant validation logic in `detectLocalExtrema()` within `src/services/hydrographic/validationStatistics.ts`. Specifically, two consecutive point-validation loops were executing over the water level time-series points.

This audit and remediation deliverable:
1. Eliminates the redundant, legacy second validation loop while preserving the single authoritative, strict calendar-aware validation pass.
2. Preserves strict ISO 8601 UTC calendar date validation (`isValidCalendarUtcIso`), normalized millisecond duplicate detection, exact millisecond synchronization, and finite numeric checks.
3. Preserves deterministic chronological sorting without mutating input arrays.
4. Verifies that all production safeguards, numerical integrity controls, and persistence contracts remain completely untouched.

---

## 2. Original Defect and Root Cause

### 2.1 Defect Description
In `src/services/hydrographic/validationStatistics.ts`, `detectLocalExtrema(points)` performed two distinct validation passes:
- **Pass 1 (Authoritative):** Evaluated every point prior to series length checks. Enforced:
  - Non-null object checks.
  - Strict calendar ISO 8601 UTC format (`YYYY-MM-DDTHH:mm:ss[.sss]Z`) via `isValidCalendarUtcIso()`.
  - Date validity and finite `timeMs`.
  - Exact synchronization between `timestampUtc` and `timeMs`.
  - Finite `heightMeters`.
  - Duplicate detection indexed by normalized millisecond timestamp (`timeMs`), preventing duplicate entries that use equivalent ISO strings (e.g. fractional vs. whole seconds).
  - Validation before returning for datasets with fewer than three points (`if (points.length < 3) return [];`).
- **Pass 2 (Legacy / Redundant):** After the `points.length < 3` check, a second `for` loop iterated over `points` using a legacy, less-strict regex check (`typeof p.timestampUtc !== 'string' || !p.timestampUtc.endsWith('Z')`) and string-based timestamp duplicate detection (`seenTimestamps.has(p.timestampUtc)`).

### 2.2 Root Cause
During the incremental integration of strict calendar validation and short-series safety checks in earlier PRs, the new authoritative validation block was placed at the top of `detectLocalExtrema()` to fail fast on invalid 1-point and 2-point datasets. The existing loop lower down in the function was inadvertently left intact, creating duplicate iteration overhead and maintaining dead, less-strict legacy validation code.

## 3. Exact Files Modified

1. **`src/services/hydrographic/validationStatistics.ts`**
   - Removed the redundant second validation loop (lines 296–333) and duplicate comments.
   - Retained the single authoritative validation pass.
   - Retained the short-series check (`if (points.length < 3) return [];`).
   - Retained non-mutating deterministic chronological sort (`[...points].sort((a, b) => a.timeMs - b.timeMs)`).

2. **`tests/tideValidationEngine.test.ts`**
   - Augmented the regression test suite for `detectLocalExtrema` to explicitly verify that the input points array is not mutated during execution.

## 5. Regression Testing & Test Coverage

The entire regression suite in `tests/tideValidationEngine.test.ts` was executed to verify all validation constraints:
- **Invalid ISO Timestamps Rejected:** Verified strings without 'Z', malformed formatting, and invalid tokens are rejected (`Invalid ISO 8601 UTC timestamp`).
- **Impossible Calendar Dates Rejected:** Verified rejection of invalid calendar dates including Feb 31, Month 13, Hour 25, Minute 60, Second 60, and Feb 29 in non-leap year (2026).
- **Leap Year & Century Handling:** Verified leap year `2024-02-29` and years `0000–0099` (e.g. `0000-01-01T00:00:00Z` and `0050-06-15T12:00:00Z`) are accepted without century offset distortion.
- **NaN / Infinity Rejected:** Non-finite `timeMs` and `heightMeters` immediately throw descriptive errors.
- **Timestamp Desynchronization Rejected:** Mismatches between `timestampUtc` and `timeMs` are rejected (`Desynchronized point`).
- **Duplicate Millisecond Detection:** Normalized millisecond timestamp collision detection verifies that equivalent ISO strings representing the same instant (e.g. `2026-11-08T00:00:00Z` and `2026-11-08T00:00:00.000Z`) are rejected.
- **Short-Series Behavior:** Invalid 1-point and 2-point series are validated and rejected before returning; valid datasets with fewer than 3 points return empty arrays (`[]`).
- **Deterministic Chronological Sorting:** Unordered valid points produce deterministic chronological extrema.
- **Immutability:** Input points array order and properties remain unchanged after calling `detectLocalExtrema()`.
